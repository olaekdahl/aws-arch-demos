EC2 Instance Type Comparison

A representative cross-section of EC2 families. Pick the right instance by matching its family (vCPU:RAM ratio, accelerators, network) to your workload — not by raw price.

Default AMI for these demos — Amazon Linux 2023

All Module 4 scripts launch al2023-ami-kernel-default-x86_64, fetched via the SSM Public Parameter /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64 so you always get the latest patched build.

Optimized for

  • Long-term support (5 yrs) on a Fedora-derived base
  • Fast boot, minimal package set, SELinux enforcing
  • Pre-installed amazon-ssm-agent, cloud-init, awscli-2
  • Deterministic kernels via kernel-default (vs. older AL2 kernel-5.10)
  • Lower attack surface than full distros (no GUI, no Java by default)

Best use cases

  • General Linux workloads on EC2 / ECS-on-EC2 / EKS nodes
  • Containers, web/API tiers, batch jobs, ML inference VMs
  • Anywhere you previously used Amazon Linux 2 and want LTS
  • SSM-managed fleets (agent already running, no SSH needed)

When to pick something else

  • Ubuntu — broader package ecosystem, GPU/ML tooling
  • Bottlerocket — purpose-built minimal container host
  • RHEL / SLES — vendor support contracts required
  • Windows Server — .NET Framework, AD, MSSQL

How to choose — a 30-second mental model

1. Start with the family letter

T burstable · M balanced · C CPU-heavy · R/X RAM-heavy · I/D local NVMe · G/P GPU · Inf/Trn AWS ML silicon.

2. Then the generation number

Higher = newer silicon = better $/perf. A m7i beats m5 on almost every metric at similar list price. Skip generations only when you need a feature (e.g. NVMe local on i4i).

3. Then the suffix

g = AWS Graviton (Arm, ~20% cheaper, ~40% better perf/$ — but rebuild your AMI). i = Intel · a = AMD · n = network-optimized · d = NVMe local SSD · z = high-frequency.

4. Burstable (T) caveat

T-family CPUs run at a baseline (e.g. 20% on t3.micro) and earn credits when idle. Sustained 100% CPU exhausts credits and either throttles you or charges unlimited mode surcharges. Never use T for steady production workloads.

5. Spot vs. On-Demand vs. Savings Plans

Spot ≈ 70–90% off but interruptible (2-min warning) — great for stateless / batch. Savings Plans / Reserved ≈ 40–60% off for 1- or 3-yr commits — great for steady fleet baseline. On-Demand for bursty / unpredictable.
